# Opportunity Comparison Framework (Phase 3 Only)

**Do not score opportunities yet.** First gather evidence and interview/experiment results. Different objectives require different weights.

## Criteria and interpretation

| Criterion | Strong evidence looks like | Warning |
|---|---|---|
| Problem severity/frequency | Recurrent tasks with measured time/cost/rework | Mild aesthetic complaint |
| Differentiation | Unsolved workflow confirmed against incumbents | A feature rebranded as 'AI' |
| Engineering feasibility | Solo scope, clear dependencies, testability | Complex integration/support burden |
| Existing code reuse | Audited, licensed, proven component-level reuse | Old repo exists so product is easy |
| Commercial viability | Reachable buyer, current spend, pilot commitments | Broad revenue projections |
| Competitive position | A wedge incumbents deprioritize or struggle to copy | Easy UI tweak incumbents can ship |
| Maintenance burden | Supported integrations and manageable ops | Fragile scraping/OEM/platform policy |
| Portfolio value | Security, testing, systems design, failure handling, deployment | Toy dashboard |
| Learning value | Relevant skills and owner comprehension | Opaque AI-generated stack |
| Validation accessibility | Real reachable interviewees and low-cost tests | Anonymous assumed audience |

## Three rankings after evidence

### A — Best engineering portfolio project

Emphasize demonstrable technical depth, explanation, reliability, security, testing, operational realism and learning; still enforce legal/safety feasibility.

### B — Best potential commercial opportunity

Emphasize painful recurring problem, buyer access, distribution, budget, switching resistance, competitive alternatives and maintenance economics.

### C — Best balance

Emphasize combined feasible build, credible customer problem, distribution, and owner time. Penalize any high-uncertainty premise that would invalidate the idea.

## Scoring policy

If using scores, choose explicit weights **before** comparing options, use coarse 1–5 anchored scales, record confidence (`high`/`medium`/`low`) and include a sensitivity analysis. Unknown values are **unknown**, not automatically neutral or favorable. Do not add precise decimals that imply measurement. Document why a candidate wins and the top 3 ways the decision could be wrong.
