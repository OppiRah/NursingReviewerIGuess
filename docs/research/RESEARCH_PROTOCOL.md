# Research Protocol — Current Claims, Counterevidence and User Pain

## Principle

Research to **disprove** attractive assumptions. No invented scarcity, user pain, comparative accuracy, market size or income potential.

## Search coverage by category

1. At least 2 established competitors, 1 smaller/specialized competitor, and 1 open-source/free/manual alternative **where they exist**.
2. Official product docs, current pricing pages, public roadmap/changelog and open-source repositories.
3. Independent experience: primary Reddit threads, GitHub issues, HN, public support/community posts and substantive YouTube demos where relevant.
4. Search for incumbents *already solving* each claimed gap.
5. For local opportunities, search Philippine-specific competitors and real purchasing/workflow context; do not generalize from US tools.

## Data capture for product claims

Record date accessed; country/currency; individual/team/enterprise target; current vs beta/announced; free-tier limits; included seats/credits; monthly/annual billing; hosted/self-hosted; data-export availability; integrations; security posture only where documented; and URLs. If blocked, mark unavailable and optionally use dated reputable secondary source, transparently labeled.

## User-report standards

Include original thread/issue URL, month/year, task context, attempted solution, reply/resolution, vendor explanation, dissent and post age. One post = one anecdote, not a market trend. Do not quote selectively: look for users satisfied with the same product.

## Open source review

Check LICENSE, release history, last meaningful activity, issue backlog and actual supported platforms. Stars are not adoption or customer satisfaction. README feature claims are not reliability benchmarks. Verify whether source/license permits commercial redistribution before recommending reuse.

## Competitive workflow comparison

Compare complete tasks (time-to-value, configuration, human handoffs, export/review and rollback), not just a checklist of features. Clearly state if no hands-on test was performed. If benchmarking, use legitimate test data, identical workflows and reproducible measurement; do not fake results.

## Gap hypothesis template

**User** → **trigger** → **current workflow** → **pain/frequency/cost** → **incumbent solution** → **what remains** → **proposed improvement** → **evidence** → **assumptions** → **cheap falsification** → **incumbent replication risk**.

## Deliverable acceptance

- Source register IDs for material claims.
- Opposing evidence shown fairly.
- Dates / prices / region disclosed.
- All unknowns labeled.
- No product selected from Phase 1 alone.
- A reviewer can click through links and replicate the argument.
